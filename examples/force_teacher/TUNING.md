# FORCE_POS 夹爪调参

## 启动与配置

```powershell
uv run --no-sync python examples/force_teacher/b601_tuner.py
uv run --no-sync python examples/force_teacher/b601_tuner.py --smoke-test
```

先加载当前 B601 ID7 校准文件，确认闭合方向、端口、X518 通道映射、增益与限制。保存设置仅保存配置，不会自动启动运动；重新加载校准后必须重新读取只读参考。

连接默认只读。显式启动使用同一校准后端与唯一 owner；界面通过参数消息与回执显示请求值和生效值。停止后等待清理完成再重新连接。

Windows 原生串口调整正读写超时时，只更新 `COMMTIMEOUTS`，避免在每轴查询或命令前重复重配整端口。原来的绝对截止时间、毫秒取整、读取/发送预算与过期拒绝均保留，不通过增大预算或改变夹爪参数规避超时。非原生串口及阻塞/非阻塞模式切换继续沿用 pyserial 行为。

`b601_ip_parameters.template.json` 是待填写的配置模板。根目录的 `b601_ip_parameters.json` 与 `b601_ip_parameters_communication.json` 是本机文件，不纳入版本控制。旧设置可读取迁移，原文件不会自动改写。

参数解析、保存与运行配置构建统一由 `lerobot.force_control.tuning` 提供，界面只负责编辑和提交。新保存格式为 v6：夹爪跟随 / 接近速度上限使用 `gripper_follow_speed_deg_s`，接触平均力阈值使用 `contact_force_threshold_N`，并保存 102 连接参数。v1–v5 JSON 和旧 Teacher YAML 仍可读取；旧 `approach_speed_deg_s` / `approach_force_threshold_N` 分别映射到这两个字段，旧新同名含义字段同时出现会被拒绝，不猜测优先级。旧 kg 目标继续按 9.80665 N/kg 转换；增益、速度、限位及底层协议值均不随迁移改动。旧文件的主臂端口默认为空，加载文件不会自动选择或启动 Teacher。

## Teacher 主从夹爪

1. 停止并断开，在“其他设置”中解锁并填写 102 主臂串口，默认使用 `protocol_v1` 只读传输；主从串口不能相同。主臂默认目标采样率为 50 Hz，与 100 Hz 的夹爪控制调度独立。
2. 加载校准与个人参数，设置目标力、Kp/Ki、接触平均力阈值、夹爪跟随 / 接近速度上限及保护限制。
3. 点击“连接 / 只读监测”，确认从爪失能与新鲜反馈；确认机械设置后点击“Teacher 主从夹爪（使能）”。控制进程先验证新鲜主爪读数，再准备并启动 ID7。
4. 运行中使用“应用实时参数”；请求值与生效值以 owner 回执区分。主臂连接、方向和校准必须停止并断开后修改。

| 状态                | 行为                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `FOLLOW`            | 跟随映射后的主爪目标，两向变化率受同一跟随速度及既有 Safety 限制；平均力达到阈值后接触接管 |
| `FORCE_TRACK`       | 持续跟踪设定目标力；力回落不退出，主爪继续闭合不接管                                       |
| `FOLLOW_WAIT_CLEAR` | 人主动张开后跟随；力低于阈值且出现新的闭合意图后重新允许接触接管                           |

接触参考使用当时从爪实测位置。102 原始角度经过原有方向、解绕与限位映射后，已处于从爪的角度坐标，直接比较即可。退出要求接触之后的新主臂样本确实向张开运动，并越过接触从爪参考，且不要求当前从爪重新闭合。界面显示映射主爪位置和已提交的接触参考。

接触位置和状态转换仅在成功提交命令后确认。传感器、主爪或从爪反馈过期时停止；重复读缓存不会刷新指令时效。停止按钮和 Esc 保持可用，主臂只读线程及 B601 owner 完成清理前禁止重开。

冻结、指定位置或恒速接近等手工操作会退出本次自动跟随；恢复 I-P 按独立力控语义运行，主臂新鲜度检查持续到会话停止。重新进入混合 Teacher 需要停止后再次显式启动。默认仍为单夹爪。

## 正常全臂遥操准备

现有 `run_force_pos_teacher.bat` 和 `uv run --no-sync python examples/force_teacher/b601_tuner.py` 默认加载项目根目录的 `b601_ip_parameters.json`，自动显示六臂官方 MIT 配置。无需选择、保存或预检草稿文件；打开面板不会连接设备或使能。`--settings-file <路径>` 可指定已有夹爪参数文件，`--gripper-only` 保留单独夹爪主从入口。

六臂直接使用原生 `RebotB601FollowerConfig`：Kp `[45,45,45,8,9,8]`、Kd `[12,12,12,1,1,1]`、`send_mit(q, 0, Kp, Kd, 0)`，绝对范围为官方限位与已加载校准的交集。SDK 将前三轴 Kd=12 编码为 5，摘要显示请求值与编码值。官方 `max_relative_target=None` 表示不另设逐帧幅度；官方没有的对齐、预载容差及命令间隔门槛同样显示为“默认关闭”，不是缺失必填参数。原已确认的 q0±100° 包络保留在六个机械臂关节上。夹爪沿用当前工作目标范围、校准硬范围和逐帧限制，不再按启动位置额外裁剪 ±100°；正常张开或闭合跨越该距离不会触发机械臂参考包络故障。诊断验收模式仍保留原七轴包络。

“正常全臂遥操”每次启动都从当前面板生成配置，夹爪的 FORCE_POS 速度码、驱动、I-P、目标力、Safety、传感器和可选时长/行程沿用当前参数。全臂页与夹爪页共用目标力及现有机械确认，不另填或自动代勾物理确认。停止、断开、重新校准后重新取得参考的流程保留。

全臂页上方的“运行范围与启动保护”可以修改“六臂距启动位置允许范围 ±(°)”（原默认 100°）、启动对齐容差、失能预载容差、返回 / 接管容差、主臂反馈最大年龄、命令最大间隔和看门狗。参考范围必须为正数，可以显式改大或改小，最终仍与各轴工作范围及校准硬范围取交集。夹爪独立沿用夹爪页的限制。可选容差和命令间隔留空或“默认关闭”表示不启用额外限制。

下方“六臂工作目标范围”显示各轴校准硬范围，并提供工作下限、上限；七轴参数表提供六臂 MIT Kp/Kd 和每拍目标偏差限制。顶部“保存参数”会把这些全臂选择与夹爪设置一起保存到同一参数文件，重启或加载后恢复，下次会话采用当前表单。参数格式升级为 v8，旧 v1–v7 文件保持只读兼容，原文件不会因加载而改写。保存不包含启动参考、机械确认或使能状态；限制修改后需停止、断开并取得新参考再启动。校准、原始超力、过期数据和急停保护继续强制校验。

“六臂 MIT 参考”提供各轴速度参考（°/s）和前馈力矩（N·m），默认沿用原来的 0。速度参考是阻尼项的参考，不是速度上限，也不会自动估计主臂速度；手填常数可能改变静态偏置。超出本次设备映射范围的请求在任何使能前拒绝。顺序启动阶段始终使用零速度 / 零前馈预载并核对位置，用户所填参考仅在启动完成后的正常控制帧应用。Kp/Kd 请求值与 SDK 编码有效值分别显示，现有 Kd=12 请求仍编码为 5，没有自动选择新的物理增益或补偿力矩。

“夹爪控制”页的 FORCE_POS / 调度设置可修改控制目标频率、分段休眠上限、读取 / 发送 / 周期截止预算；“其他设置”可修改主臂采样频率、主臂读取预算与界面刷新频率。分段休眠参数控制 GUI 单 owner 调度器的停止检查粒度，不改变已逾期节拍跳过、不重放的规则。界面同时显示按控制 tick 计数得到的近期实际频率，以及各轴反馈与最新主臂目标的差值。反馈早于同拍发送，这个差值包含动态滞后，不能当作同拍命令已经执行后的到位误差。

启动阶段分段保存的传输审计与正常控制、故障清理审计按原始顺序统一核验，不能排序、补号或忽略真实缺口。UI 只显示审计计数摘要，完整事件保留在原始 `control.jsonl`。重复错误在界面合并计数；历史日志保持原样。运行中收到停止请求标为 `user_stop`，实际启动阶段收到停止才标为 `user_stop_during_startup`；即使是停止中断接收，未完成命令仍保留 unknown，不会伪造成功或硬件 ACK。

全臂页仍允许显式编辑 MIT 参数并选择高级配置；默认入口会直接使用当前编辑值，不要求另存草稿。显式选择外部 operator 或 micro 诊断文件时继续使用该文件的校验流程。micro 的数值、短时和证据要求不加到默认入口。

正常全臂控制优先使用上一批命令收到、尚未消费且仍新鲜的七轴反馈，保留原接收时间、序号和位置；缺轴、过期或已消费时重新查询，不把重复读缓存算作新反馈。界面只接收启动证据摘要，完整证据仍保存在控制日志和运行结果中，避免每个周期重复复制大量启动回包。力传感器的最新因果样本选择使用等价快速路径，未来或尚未到达的样本仍不参与控制。

## 故障后恢复界面

“故障恢复 · 连接自动复核”版窗口会在 IPC 断开或界面更新异常后继续处理停止、运行结束与资源关闭回执，显示错误并恢复按钮。旧窗口不会自动加载磁盘上的更新，需要从现有启动入口打开新版窗口。

故障清理发送原有七轴失能命令，并在原截止时间内重新查询七轴状态；已知旧回包单独保留为历史证据，不能代替新的失能反馈。只有完整的新失能观测和资源关闭证据满足原有条件，才恢复运动入口。上次全臂退出状态未知时，点击原有“连接 / 只读监测”会先自动复核七轴：等待旧 owner 退出、旧串口确认关闭，使用同一端口和校准取得七轴新鲜失能反馈，关闭复核连接并保存独立回执，然后接入原来的夹爪与力传感器只读监测。取得新参考并勾选原有机械确认后，再点击启动即可；无需另外寻找恢复按钮。直接点击启动也会引导到这个只读连接流程，不会在复核后自动使能。

“全臂只读复核（不使能）”保留为独立复核入口。两种复核均不发送使能、失能、位置或参数写入，不改变原参数；停止、退出或端口与校准变化会取消后续连接。任一轴仍使能、反馈缺失或复核关闭失败时，会显示具体原因，不接着启动控制。

## 完整示范录制

“示范录制”页提供数据目录、任务、物体、接触条件、相机 JSON、续录、episode 数量、预览和完整性状态。默认主数据/视频为 30 Hz，目标为 10 条；实际频率以记录清单为准。录制要求完整七关节 owner，单夹爪会话会明确拒绝完整示范录制。

**开始录制不会使能；“结束并保存”不追加机械动作，控制会话继续。** 在允许的位置放下、手动张开后再结束 episode，并明确选择人工任务结果。独立的“释放并结束采集”仍会执行受限张开并结束控制会话；停止 / Esc 优先停止并将未完成条目标记为中断。

操作步骤、相机 JSON、只读验证命令、数据标签和当前验收边界见 [完整示范录制说明](DEMONSTRATION_RECORDING.md)。参数文件保存按钮仍保存原夹爪参数，示范录制表单需要在本次会话中明确填写。

## 控制与单位

### 工作终点与硬保护范围

“工作目标下限 / 上限”限制正常发出的目标；校准文件的范围用于实测位置硬保护。两者在界面中分开显示。例如本机已确认工作终点为 −270°、机械硬下限为 −300°：启用工作范围 `[-270, 0]` 后，张满时目标保持在 −270° 内侧的可编码位置，程序继续运行，不会继续命令张到 −300°。轻微实测过冲仍在硬范围内时，保持原工作目标；超出硬范围仍停止。

已有加速度限制启用时，跟随和定位模式会根据剩余工作行程提前限制目标变化率；没有自动选择或启用新的加速度值。该限制改善命令轨迹，不能保证实际机构完全没有过冲。

校准或工作范围修改后，停止并关闭旧窗口，重新启动，加载保存的参数文件，并重新获取只读参考；磁盘修改不会自动改变正在运行的会话。正常反馈继续严格检查硬范围。故障失能时，越界位置作为异常证据保留，不能妨碍识别有效的失能状态反馈；这仍不等于硬件 ACK 或机构已经静止。

- 目标力及死区为 N；Kp 为 °/N，Ki 为 °/(N·s)。Ki=0 时，恒定的力误差不会产生持续积分闭合。
- I-P 使用本周期真实 dt 和相邻成功提交的力样本；修改目标力不制造比例冲击。
- 恒速接近使用接近速度；达到平均力阈值后切入 I-P。指定位置移动另有定位速度。
- 接触时消除之前下发但尚未到达的闭合目标余量；若速度限制只允许部分消除，后续周期继续对齐。真实上次下发目标始终保留，对齐期间不标记为有效力控训练样本。
- 闭合／张开最大速度是外环目标变化率限制，单位 °/s。电机速度码是底层 FORCE_POS 字段，1 码为 0.01 rad/s；驱动百分比也不是目标夹持力。
- GUI 的控制调度目标为 100 Hz；实际频率与超时情况以日志为准。调度超时跳过旧节拍，不补发积压命令。
- X518 每拍选择最新已到达的因果有效样本，左右求平均用于控制；左右分别进行原始力上限保护。

## 记录与验证边界

运行资料位于 `outputs/force_teacher_tuning/`，包含参数、校准来源、候选目标、安全后目标、实际提交目标与退出证据。

### 自动阶段标注与完整采集

点击显式使能后，控制进程先启动记录，再启动 owner 和运动。一次运行的 `control.jsonl` 保留全部控制周期，包括准备、跟随/接近、接触交接、力控、释放和故障；`raw_force.jsonl` 独立保存原始速率的力样本。不会因为 `label_valid=false` 删除某行。连接后的只读预览发生在另一监测进程中，不属于这次控制采集。

正常完成时点击 **“释放并结束采集”**：通过原有受限 RELEASE 状态机张开，记录直到 DISABLED，再关闭文件。该操作会使夹爪张开，应在允许释放的位置使用。释放期间继续检查主爪、从爪与力反馈；重复结束请求及新的运动/调参请求会被拒绝。**“停止”与 Esc 仍立即停止，不会先执行释放。** 中途停止或故障的日志仍保留，但不能算作正常释放完成。

新记录声明 `force_capture_annotations_v1`。保留原 `phase` 和 `label_valid` 兼容既有读取，新增字段如下：

| 字段                                               | 含义与训练用途                                                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `phase_at_tick_start`                              | 本周期进入时的控制状态，尚未处理本周期的操作事件。                                                            |
| `phase_before`                                     | 处理已接受事件后的决策前状态；没有走到决策的故障周期保留入口状态。                                            |
| `phase_after`                                      | 周期结束状态，与原 `phase` 相同，包含提交/故障结果。不能提前作为本拍动作的输入。                              |
| `phase_changed`                                    | 入口状态与结束状态是否不同，配合原 `event`、`transition` 定位交接。                                           |
| `capture_stage`                                    | 周期结果的粗阶段：`idle`、`approach`、`contact_transition`、`force_control`、`release`、`position`、`fault`。 |
| `contact_estimate`                                 | `no_contact` / `contact` / `unknown`。使用同一次因果力选择的均值与已有接触阈值比较，不改变控制器。            |
| `contact_estimate_valid` / `contact_estimate_rule` | 标记接触估计是否有依据及其规则版本；无阈值、无效、过期或未来力样本时为未知。                                  |
| `action_label_valid`                               | 用于各阶段位置变化率模仿的保守有效性标记：连续成功提交、有效新鲜反馈、命令增量一致且无故障/保护介入/超时。    |
| `label_valid`                                      | 原有连续 FORCE_TRACK 的力控动作标签；不扩展为接近或释放标签。                                                 |

`approach` 包含 APPROACH 和人工 FOLLOW；`release` 包含 RELEASE 和 FOLLOW_WAIT_CLEAR，但原控制状态始终保留，两者不能混称为主动释放。接触交接包括切入力控的周期及尚在消除闭合目标领先量的周期。`force_control` 不等于稳定保持；FORCE_TRACK 中力回落时，接触估计仍可为 `no_contact`。均值阈值估计也不表示两指均已接触。

`u_label_deg_s` 始终根据最终成功提交的目标位置增量计算，不是实测机械速度。`action_label_valid` 只说明命令监督的时序与有效性，不等于示范质量已验收或硬件到位。人工跟随、接触对齐与保护裁剪的区别仍可从模式、候选/最终命令和裁剪字段中追溯。

第一版力控训练可对 `label_valid` 为真的时刻计算动作损失；学习完整动作过程时，可另用 `action_label_valid` 并按阶段评估。两个标记都只是损失掩码，不是删行条件：前接触和切换时的有效观测仍应保留在因果历史里，失效传感数据另行屏蔽，不能跨故障/重置拼接出假连续轨迹。阶段预测监督也应使用独立掩码，不能将拍末阶段或事后判断倒灌为决策输入。

运行下列只读命令检查文件完整性及 `capture_summary`（把末尾目录替换为实际日志目录）。摘要分别报告阶段覆盖、接触估计、动作标签数量和是否观察到正常主动释放完成；**文件完整不等于一次任务覆盖了全部阶段**。旧日志继续按原格式校验，不凭空补造新标签。
