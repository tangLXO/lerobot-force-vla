# FORCE_POS 交付范围与回退

## 2026-10-31 日常入口统一

日常采集统一通过根目录 `run_force_pos_teacher.bat`，本机桌面的“Force-VLA 数据采集”快捷方式直接指向该脚本，工作目录为 `force-vla` 主线。移除重复的示例批处理入口；本机旧实验的 4 个启动/续录脚本移至仓库外归档。原 Tk 面板、离线演示和启动检查继续通过同一入口的 `--legacy-ui`、`--demo`、`--smoke-test` 参数使用。

快捷方式不附带旧实验配置或 `--connect`，启动仍只加载日常参数，连接和运动需要界面操作。X518 独立硬件检测工具及历史源码快照保留；本次不改变通信、控制或数据契约，改动折入原界面和文档提交。

## 2026-10-31 120 μs 连续录制与问题详情

Qt/Tk 日常入口默认 `cached`、120 μs 最小发送间隔；显式命令行参数优先于 `MOTORBRIDGE_TX_GAP_US` 环境变量，再使用默认值。非法值在连接前拒绝，界面显示实际选择及来源。续录仍严格匹配原数据根的通信策略；间隔不一致时提示原值与可用命令，不改写旧数据。

连续录制在发布“已保存”前准备下一段编码器，避免下一次开始时阻塞相机读取；预先建立有界控制帧队列，保留录制启动期间的完整帧。首要录制错误在 Raw 清理之前发布，清理错误不覆盖原始原因。整批核验仅排除未注册任何保存证据的失败隔离事务，仍检查主表每段恰有一个完整 Teacher 附件，验证过程严格只读。

新增全局“问题详情”：可查看常见问题说明、完整原始错误、关联日志并复制，窗口内保留最近 10 条。正常人工停止 `user_stop` 不列为控制故障，真实故障、录制失败和退出待复核仍显示。

操作者在 `outputs/validation_120us_20261031_123308/dataset` 完成 5 段、32,664 帧、259,905 条原始力样本；5 段的主表、双动作、Raw/Sync、哈希及双摄完整解码通过，检查前后数据树、大小和修改时间不变。录制中没有硬超时或发送失败；6 次孤立软超期，最大工作耗时 22.023 ms。2 次早期失败保留为隔离证据，未混入主表；修正后最新会话连续保存 3 段并由操作者停止。

仍有内容质量问题：第 4 段 2 N 保力存在约 5.6 Hz 波动，稳态片段平均绝对误差约 0.589 N；腕部画面发虚；第 5 段约 98% 为 `FOLLOW_WAIT_CLEAR`。本次不据此归因于发送间隔，也不将存储完整等同于保力或训练效果验收。合并审查不追加硬件动作，个人配置、实机数据和诊断报告保留。

本次改动按职责折入已有采集、界面和文档提交，不新增主线提交。以下保留较早交付时的配置及验证记录。

## 2026-10-31 日常启动默认值对齐

操作者要求日常启动沿用已验收的异步反馈读取。修正 Qt 与 Tk 入口未同步验收参数的遗漏：无参数启动七轴会话默认 `cached`、发送间隔 `1000 μs`，当前个人采集配置仍为 50 Hz。根目录启动脚本和 `--legacy-ui` 同样生效，显式命令行参数可覆盖。单夹爪定位、通用底层配置默认值、I-P 参数、安全限值和个人参数文件保持原状。

本次仅调整入口参数并进行离线回归；没有连接或操作硬件。下方及专项验证报告中的“默认 sequential”为当时状态，原始验收记录不改写。

## 2026-10-30 采集主线交付

按操作者已完成的数据采集功能验收，将 `codex/teacher-capture` 整理合入 `force-vla` 主线，保留已有提交历史。新增改动按以下边界提交：

1. B601 显式 pipelined/cached 通信、绝对期限、接收尾部处理、停止标志与源码路径核对；默认仍为 sequential。
2. 录制契约 v2 的限幅前/实际提交双动作、通信来源、快速保存、可选视频解码、严格只读核验与 Hub 附件兼容。
3. Qt 中文工作台、独立预览、异步会话、整批核验及结果查看，保留原 Tk 入口。
4. 操作说明与历史专项验证记录；Raw 样本计数按实际 Parquet 修正，历史失败和覆盖边界保留。

本次交付不变更 I-P 参数和默认通信模式，不引入训练或部署功能。“结束并保存”不追加机械动作；完整视频解码与人工任务结果分别记录。新录制采用 `teacher_capture_contract_v2`，旧 v1 根目录继续只读加载和核验，不原地补字段或迁移。

合入前回归发现并修复录制子进程退出竞态：取消立即扣留完整标记，正常关闭仍按序接收 Raw/控制尾部和关闭消息；关闭消息发送失败或父进程退出时仍按失败清理，不伪造尾部完整性。

分支清理前将所有引用及未提交源码备份到仓库外的 Git bundle 和文件快照。旧实验分支只归档，不合入当前采集实现；`main` 保留为上游跟踪线。后续界面优化、操作命令精简及旧参数兼容已按职责折入原控制、界面和文档提交，不增加提交数量。采集工作区的数据、日志和个人配置迁入主线目录并核对后，删除 `codex/teacher-capture` 分支及其独立工作区，后续统一使用 `force-vla`。同名但不同的数据集整根另名保存，不混合文件。可用 `git bundle list-heads <备份.bundle>` 查找旧分支，再用 `git fetch <备份.bundle> <旧引用>:refs/heads/codex/recovered-<名称>` 恢复到新分支。

## 回退

先保存当前未提交修改，再使用 `git switch -c codex/forcepos-baseline 60cf2ac0` 创建独立基线分支，或使用 `git switch -c codex/forcepos-original 88574f6d` 恢复原开发快照。新分支名已存在时另选名称。切换旧快照前将当前被忽略的个人参数另行保存，避免同名已跟踪文件冲突。

这些操作不重写远端历史。返回基线会移除混合 Teacher 与共享参数重构；完整备份包含原先暂缓的实验代码。

软件测试、假设备轨迹和 GUI 启动检查仅证明软件行为。后续实机验收需明确运动范围和停止条件，并分别核对主从映射、控制时序及停止后失能反馈；`hardware_ack` 保持 `unknown`，不以提交成功代表物理到位。
